# ATS Guidelines

Use this reference when the user asks for an ATS-friendly resume or provides a job description.

## Structure

Use simple section headings such as Summary, Education, Experience, Projects, Skills, Certifications, Publications, and Awards. Avoid complex tables, text boxes, headers/footers, icons, decorative rating bars, and multi-column layouts unless the user explicitly requests a designed document.

Prefer reverse-chronological structure for industry resumes. Use clear employer, role, location, and date lines.

## Keywords

Extract important keywords from the job description:

- Role title and adjacent titles.
- Required tools, programming languages, platforms, methodologies, and domain terms.
- Core responsibilities and deliverables.
- Seniority cues such as lead, own, stakeholder, strategy, production, research, or client-facing.

Integrate keywords only when supported by the candidate's background. Do not keyword-stuff or add unsupported tools.

## Length

Default to one page for students, early-career candidates, and focused industry applications. Two pages are acceptable for senior roles, research-heavy profiles, or substantial publications/projects.

## File-Oriented Advice

If creating a Word or PDF resume, keep the source layout simple and readable. If the user needs ATS upload reliability, recommend submitting `.docx` when the application portal permits it, with PDF used for human-readable sharing.
